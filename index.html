Landing ejc3's five open cmux PRs

manaflow-ai/cmux · #7397 #8555 #7214 #7193 #8721 · roll-up #12561 · 2026-09-28

Five PRs are open, and all of them merge cleanly into main with their tests passing. #7397 fixes where sidebar links open and can land any time. The other four improve remote tmux. The biggest, #8721, adds EternalTerminal as a transport and makes remote tmux usable on hosts that ask for a security-key tap on every new connection.

The ask: a branch namespace in manaflow-ai/cmux, for example ejc3/*, so the remote-tmux work can land as a stack of small commits with one PR each. GitHub cannot stack PRs from a fork.

What users get

  • #7397 Sidebar links follow the open-externally list. The sidebar's pull-request and port links now honor browser.urlsToAlwaysOpenExternally, like terminal links already do, instead of dead-ending in the built-in browser.
  • #8555 A reconnect can ask you to sign in. When a host needs a password, MFA or a key tap to reconnect, cmux opens one sign-in per host and brings the mirrors back, instead of freezing them and retrying forever.
  • #7214 ⌘N in a mirror window opens a session on that host. No trip back to a terminal for a new remote session. New Local Workspace (⌃⌘N) still opens local work there.
  • #7193 Each host gets its own color. A host's workspaces share a stable sidebar color, and duplicate names show their host. Both are behind beta flags.
  • #8721 EternalTerminal support, and remote tmux that works where every connection costs a tap. A host can now use EternalTerminal instead of ssh, directly or through a broker, so its connection survives sleep and network changes. With the multiplexer beta, all of a host's sessions share that one connection and one tap. A failed attach now says why instead of opening an empty workspace.

The plan: one stack

#8721 is 116 commits and 18,032 added lines, and it already contains #8555 plus its own copies of the routing in #7214 and the host lookup in #7193. Reviewing it whole is a lot, and splitting it into independent PRs would take days of rework because its parts depend on each other. The plan is to land it as a stack instead: eleven commits on one branch, one PR each, landed bottom-up, each one leaving main green. Where the new transports and the multiplexer need an interface, a commit with no behavior change adds it first.

The stack is posted whole and its top matches #8721 exactly, so it is tested as one piece and the early commits are shaped by what the later ones need. Each commit also builds and passes its tests on its own.

Why this order. The three PRs already open come first, so their review carries over. The start-marker fix depends on nothing and goes next. Each groundwork commit comes just before the commits that use it. The multiplexer and the ⌘N routing for multiplexed hosts call each other, so they share commit 9. Commit 10 uses parts of the transport and the multiplexer, and commit 11 uses everything below it.

Landing it. Land from the bottom. The repo squash-merges, so after each merge the stack branch is rebased onto main, the landed commit drops out, and the stack tool updates the remaining PRs. #7397 is not part of the stack and can merge at any time.

Why it needs the main repo. GitHub compares a PR against a branch, so a stack tool such as ghstack or spr pushes one branch per commit and opens each PR against the commit below it. A PR from a fork can only target branches in the main repo, so those per-commit branches have to live there.

What to review closely

Everything in the remote-tmux PRs already sits behind the remote-tmux beta. Most of it sits behind a further flag or option, so it only reaches users who turn that on. These changes reach every remote-tmux user and deserve the closest review:

  • Reconnect sign-in (commit 1, #8555). Every failed reconnect now goes through a three-way decision: the session is gone, the failure is transient, or the host needs a sign-in. A wrong answer either misses a sign-in or opens one that is not needed. The one-sign-in-per-host rule came from watching the old behavior open six tabs in 76 ms.
  • ⌘N in mirror windows (commit 2, #7214). This changes what a familiar shortcut does in one kind of window. The decision is one pure function with a four-row table under test, shown in its section.
  • Start marker (commit 4). The parser now accepts tmux's control-mode start marker anywhere in a line instead of only at its start.
  • Attach reports failures (commit 10). Attach now waits until each session has sent its windows, and reports the sessions that never do. It also treats a silent password prompt as needing a sign-in.

#7193 runs through every user's sidebar code, but with its flags off it adds one check per row. #7397 only acts on links that match the user's own list, and only on a real click or key press.

#7397 Send sidebar links through the external-open rules, and escape only on a real user event

Branchbrowser-external-open-host-patterns 258e3f76adSize3 commits · 12 files · +562 / −23 (79 product source lines; the rest is tests and fixtures)StateReady for review · 19 reviews · 0 unresolved threadsRisklow

What it does. browser.urlsToAlwaysOpenExternally lists sites that cmux opens in the system browser instead of its built-in browser, which matters for sites that only work in a managed browser. On main, terminal links, the intercepted open command and clicks inside the built-in browser follow that list. The sidebar's pull-request and port links are the exception: they open in the built-in browser and dead-end. This PR makes them follow the list too. It also guards against pages: a link goes to the system browser only while a real key or mouse event is in flight, and a download never does, so a script cannot open the system browser on its own.

How it works. The first of three commits routes sidebar pull-request and port links through a new linkEscapesToSystemBrowser(_:), limited to web schemes. The second requires an AppKit key, left-mouse or middle-mouse event in flight before any link escapes (hasUserActivation), and never lets a download escape: WebKit reports a script's click() on an anchor as a link activation, so without this a page could open the system browser whenever it liked. The third adds UI tests with local fixture pages and a DEBUG capture sink, so CI observes the open without launching a browser.

Figure 2. When a link escapes after #7397. All three checks must pass.

How to merge

Squash merge, any time. It touches no remote-tmux file. Its UI tests (BrowserExternalOpenRoutingUITests and the fixture interaction tests) run only in CI, with a DEBUG capture sink standing in for the system browser.

#8555 remote-tmux: offer a login when a reconnect can't authenticate, instead of retrying forever

Branchremote-tmux-reconnect-auth fef5d498fdSize15 commits · 16 files · +2,251 / −14 (830 product source lines, 26 new tests in RemoteTmuxAuthTests, an acceptance doc and a harness script)StateDraft · 15 reviews · 0 unresolved threadsRiskmedium

What it does. Users whose host asks for a password, MFA push or security-key touch get their mirrored sessions back after a dropped connection. cmux stops retrying, keeps the tmux session and every mirrored workspace, opens one "Sign in to <host>" workspace, and resumes every waiting mirror for that host once the user signs in. Today the mirror freezes on its last frame. The background reconnect runs with BatchMode=yes and no tty, so it can never answer the prompt, and it retries with backoff forever.

How it works. handleStreamEnd classifies an ended stream three ways through a pure RemoteTmuxReconnectDisposition: session gone, transient, or needs a login. On a login the retry loop stops and the connection parks in .reconnecting, so the tmux session and every mirrored workspace stay intact. cmux opens a "Sign in to <host>" workspace that runs the same interactive command the CLI uses, watches the control socket with ssh -O check, and resumes every parked connection for that host once the master is up. RemoteTmuxLoginOffers keeps it to one login per host: the slot is reserved before the workspace exists and is released only when a mirror reaches .connected.

Figure 3. The reconnect paths after #8555. There is no deadline on the login wait: an MFA push can take minutes, so the wait ends on state (master up, host has no mirror left, or login closed unfinished), never on a timer.

How to merge

It is commit 1 of the stack. Without a stack, take it out of draft and squash merge it before #8721. #8721 already carries all of it, so once this lands, updating #8721 drops those changes as already applied. Landing #8721 first instead would make this PR a duplicate to close.

#7214 Make ⌘N in a remote-tmux mirror window open a session on that host, and add New Local Workspace

Branchremote-tmux-new-local-workspace 9c83edb3edSize7 commits · 17 files · +1,203 / −10 (232 product source lines)StateDraft · no reviews yetRisklow

What it does. Users working in a window that mirrors a remote host can start another session on that host with ⌘N, and it opens mirrored in the same window. Today ⌘N there opens a local workspace, and a new remote session means going back to a terminal. For local work in that window, File > New Local Workspace (⌃⌘N) does what ⌘N did before. The item appears only when ⌘N would go remote.

How it works. The routing decision is one pure function, newSessionHost(activeTabId:entries:), keyed on the active workspace rather than the window, because a window can hold mirrors from several hosts plus local workspaces. wouldNewWorkspaceSpawnRemote(in:) reads the same function for the menu item's visibility, so the item and the routing cannot disagree. performNewLocalWorkspaceAction goes through the same creation path as ⌘N with forceLocal, which skips only the remote branch and the configured-action override.

#7193 remote-tmux: tint remote workspace sidebar rows by host (origin colors, beta)

Branchremote-tmux-origin-colors f4a985c90eSize16 commits · 23 files · +1,270 / −29 (481 product source lines)StateDraft · 10 reviews · 0 unresolved threadsRisklow

What it does. Users mirroring several hosts can tell their workspaces apart at a glance. With remoteTmux.originColors.beta on, each remote workspace's sidebar row and tab takes a stable color for its host, the same in every window, and a color the user picked always wins. With remoteTmux.originHostTitles.beta on, two workspaces with the same title, such as two main sessions on different hosts, show their host after the title, without the domain the hosts share.

How it works. RemoteHostColorRegistry, owned by the controller, maps a destination to a palette slot: an FNV-1a hash picks the start, a collision probes to the next free slot, and the palette was chosen so neighbors stay distinguishable on the sidebar rail. The color and the host suffix are resolved above the row boundary into the row snapshot, and both are part of the snapshot's presentation key, so a flag toggle rebuilds exactly the rows whose color changed.

Figure 4. How a host's color reaches a sidebar row. The cache box is main's, and the per-row key is this PR's, applied in the cache's reconcile step.

How to merge

It is commit 3 of the stack. Without a stack, squash merge it after #7214. They share RemoteTmuxController.swift, but in adjacent functions. The color and the host suffix live in main's SidebarRowSnapshotCache: reconcile takes a per-row key, and the targeted refresh also rebuilds rows whose host suffix went stale when another workspace was renamed. With both flags off, the per-row key adds one flag check per row.

A mirror row never draws before its host is known. mirrorSession adds the workspace and registers its mirror, host included, in one synchronous pass on the main thread, and the sidebar rebuilds snapshots from a SwiftUI onChange on the workspace list, which runs in a later view update. A session rename re-keys the mirror but keeps the same host.

#8721 remote-tmux: EternalTerminal support, and one shared connection for hosts where every connection costs a tap

Branchremote-tmux-one-connection a43eff3d13Size116 commits · 75 files · +18,032 / −145 (6,973 product source lines, 5,592 test lines, 4,310 docs and harness lines)StateDraft · 7 reviews · 0 unresolved threadsRiskhigh

What it does. Some environments allow only one session on an ssh ControlMaster and ask for a security-key tap or MFA on every new connection. Today's remote tmux cannot work there: it opens a separate tmux -CC connection per mirrored session, so each session costs a tap, and each network drop costs a tap per session again. #8721 makes those hosts usable. With remoteTmux.multiplexer.beta on, every mirrored session from a host rides one connection, so the user taps once instead of once per session. EternalTerminal, chosen per host and usable through a broker, keeps that one connection alive across a network change or a laptop sleep, where ssh would drop it and need a new tap. That also works from a cmux launched from the Dock or Finder. And if the remote session closes or never starts while cmux is connecting, cmux tells the user what happened. Today it opens a workspace with nothing from the host in it, only a local shell. The branch also carries the work of #8555 and of two closed PRs, #8428 (the session multiplexer) and #8556 (the transport seam).

How it works. The figure shows the two transports. The sections after it cover the changes that run without a flag, the fixes that exist only with the multiplexer on, and the brokered EternalTerminal fix.

Figure 5. The two transports #8721 supports. The default keeps today's shape. The multiplexer, behind remoteTmux.multiplexer.beta, exists for hosts that allow one connection or authenticate every connection: measured against a corporate ssh broker, the old extra one-shots each ran their own MFA and the stream died on a passcode prompt it had no tty for.

The changes that are not behind a flag are the ones to review hardest, because every remote-tmux beta user's attach runs through them:

  • A mirror counts only once its connection has published a topology. attachHost waits for all mirrors at once under one deadline and drops those that never publish, saying why. Before, a stream that sent an attach block and then %exit produced a workspace whose only surface was a local placeholder shell.
  • An unanswered credential prompt before the first %begin classifies as needing a login, feeding #8555's parked-login flow, for brokers whose prompt produces no stderr.
  • The control-mode parser finds tmux's ESC P 1000 p anywhere in a line, since a login shell leaves echo and title sequences ahead of it.

Two fixes that read like default-path changes are multiplexer-only. A raw query now ends three ways (lines, a %error, or silence) and only silence triggers the reconcile's retry. Main has no raw-query path, and on this branch only the view connection and the session channel call it. Closing a host's last workspace tears down the shared stream and master before looking for a tab manager, and the shared stream exists only when the multiplexer is on.

Brokered EternalTerminal from a Dock-launched app. A broker that starts et by name finds it through PATH, and an app started from the Dock or Finder inherits launchd's minimal PATH, which lacks /usr/local/bin and /opt/homebrew/bin. Every cmux ssh-tmux --transport et --broker <name> from such an app failed at once. 238af2b123 lets a transport profile supply its child's environment: the ET profile keeps the user's PATH in order and appends the directories et installs to, and ssh inherits the environment unchanged.

How to merge

Land it through the stack as commits 4 to 11. Without a stack, land it whole, last among the remote-tmux PRs. Main is merged into the branch rather than rebased under it, because its 116 commits are its review record, and the squash merge flattens it anyway. Three commits adapt it to main's pane colors and titles: RemoteTmuxSessionSource gains paneTitleMetadataByPane, setPaneColors and removePaneColors, and the observer struct gains onPaneTitleChanged, scoped by pane in the multiplexed channel.

Without a stack

If the stack cannot live in the main repo, the PRs land one by one: #7397 at any time, then #8555, #7214 and #7193, then #8721 as a single PR. Each small PR that lands first removes its copy from #8721, about 2,700 lines in total. #8721 stays large, and its review is the main cost of this path.

Splitting #8721 into separate PRs that land in any order is possible but costly. Its later commits rewrote code shared by several parts, so each part would have to be rebuilt from the older PRs it came from and reworked to stop using its siblings' code. That is several days of work, and the stack gets the same small reviews without it.
